# チェック用の限定公開（さくらインターネット）

チェックのための限定公開の手順。本公開の手順は SPEC.md §13 を見る。

## 1. ファイルを作る

```bash
npm run build:check
```

- `dist/` と、その中身をまとめた `srhr-check.zip` ができる。
- 検索エンジンに載らない設定（`<meta name="robots">`、`robots.txt`、`X-Robots-Tag`）が付く。
- 本公開のときは `npm run build` だけを使う（この設定は付かない）。

## 2. フォルダを決める（はじめの1回だけ）

パスワードは **1つ上のフォルダ** にかけ、ファイルはその下に置く。

```
（公開フォルダ）/check/        ← ここにパスワードをかける（アップロードでは触らない）
（公開フォルダ）/check/u35/    ← ここに dist/ の中身を置く（修正のたびに上書き）
```

理由：さくらのコントロールパネルでパスワードを設定すると、そのフォルダの `.htaccess` に設定が書き込まれる。同じフォルダに `dist/.htaccess` を上書きすると、パスワードが消える。1つ上のフォルダにかけたパスワードは、下のフォルダにも効く。

## 3. パスワードをかける（はじめの1回だけ）

さくらのコントロールパネルの「アクセス制限」（ベーシック認証）で、`check/` フォルダにユーザー名とパスワードを設定する。

- パスワードは、チャットやリポジトリに書かない。チェックする人には、別の方法で伝える。

## 4. アップロード（修正のたびに）

`dist/` の **中身**（`index.html`、`assets/`、`.htaccess`、`robots.txt`）を `check/u35/` に上書きでアップロードする。

- `.htaccess` は、名前が「.」で始まるため、FTP ソフトの設定によっては見えない。「隠しファイルを表示」にする。
- 古い `assets/` のファイルは残っていても動く（ファイル名が毎回変わるため）。気になるときは消してからアップロードする。

## 5. 確かめる

- `https://（ドメイン）/check/u35/` を開くと、ユーザー名とパスワードを聞かれる。
- パスワードを入れると、タイトル画面が出る。
- ヘッダーが付いているか：

```bash
curl -sI -u （ユーザー名） https://（ドメイン）/check/u35/ | grep -iE "content-security|x-robots|nosniff"
```

## 注意

- チェックの人の進行状況は、その人のブラウザの中だけに保存される（サーバーには送られない）。
- 統計 S35 は残務（SPEC.md §15 T19）。いまの本文は使っていないので、公開には影響しない。
